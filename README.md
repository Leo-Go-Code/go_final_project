# Файлы для итогового задания

В директории `tests` находятся тесты для проверки API, которое должно быть реализовано в веб-сервере.

Директория `web` содержит файлы фронтенда.

## Созданные файлы

Директория `pkg` с тремя поддиректориями:

- `api` — содержит файлы с обработчиками API запросов;
- `db` — файлы с кодом, отвечающие за работу с базой данных.

Файлы `main.go`, `go.mod`, `go.sum` располагаются непосредственно в директории проекта.

## Описание проекта

Проект представляет собой планировщик задач (TODO-лист), который по запросу пользователя:

- добавляет задачу;
- выводит задачу(и);
- удаляет задачу;
- получает по запросу пользователя данные;
- изменяет по запросу пользователя задачи;
- отмечает задачу, как выполненную.

## Список выполненных задач со звёздочкой

- Шаг 1\*: Определение извне порта при запуске сервера с использованием переменной окружения TODO_PORT;
- Шаг 2\*: Определение пути к файлу базы данных с использованием переменной окружения TODO_DBFILE;
- Шаг 3\*: Реализация правила повторения для месяцев и недель;
- Шаг 5\*: Реализация вывода пользователю списка задач по запросу в поисковой строке.

## Инструкции по запуску кода локально

Запустите сервер командой:
go run main.go

Убедитесь в наличии файла .env с переменными TODO_PORT и TODO_DBFILE

Откройте браузер и проверьте функционал проекта, перейдя по ссылке http://localhost:7540

## Инструкции по запуску тестов

Параметры тестов в файле tests/settings.go:

```
package tests

var Port = 7540
var DBFile = "../scheduler.db"
var FullNextDate = true
var Search = true
var Token = ``
```

Значение DBFile не имеет значения, так как тест переопределяет его по переменной окружения TODO_DBFILE

Строки для запуска тестов без кэширования для уроков по отдельности:

1. go test -run ^TestApp$ ./tests -count=1
2. go test -run ^TestDB$ ./tests -count=1
3. go test -run ^TestNextDate$ ./tests -count=1
4. go test -run ^TestAddTask$ ./tests -count=1
5. go test -run ^TestTasks$ ./tests -count=1
6. 6.1. go test -run ^TestTask$ ./tests -count=1
   6.2. go test -run ^TestEditTask$ ./tests -count=1
7. 7.1. go test -run ^TestDone$ ./tests -count=1
   7.2. go test -run ^TestDelTask$ ./tests -count=1

Прогон всех тестов сразу без кэширования:
go test ./tests -count=1

## Примечания:

1. Проект реализован с небольшими отклонениями от предлагаемых в уроках структуры и названий функций и файлов.

   - Файлы `db`, которые выполняют запросы к БД находятся в поддиректории `/pkg/db` и имеют названия функций и файлов, заканчивающихся на ..Data.go. Также в данной поддиректории располагается сам файл БД `scheduler.db`.
   - Файлы `api`, которые обращаются к функциям, работающим с БД, находятся в поддиректории `/pkg/api` и имеют названия функций и файлов, заканчивающихся на ..Task.go. Также в данной поддиректории располагаются другие файлы реализующие работу api.
   - Для удобства восприятия структуры можно воспользоваться средствами визуализации (например Graphviz Preview).

2. Для удобства тестирования при запуске сервера в терминале выводятся несколько ссылок, которые возвращают файлы в браузер.

3. Для прохождения автотестов, а точнее передачи ключ=значения переменных окружения TODO_PORT и TODO_DBFILE (дополнительные задания 1* и 2*), в файл tests.yml в шаг Run local server я добавил 3 строки:
   env:
   TODO_PORT: 7540
   TODO_DBFILE: ../scheduler.db
   Никаких других изменений в исходные файлы проекта не было.

4. Несмотря на схожесть функций представленных в файлах get_datas.go и find_tasks.go, они имеют принципиальное отлицие в запросах поиска, которые помимо лимита возвращаемых задач могут включать в себя поиск по дате или слову(ам) из поисковой строки. Поскольку эти функции дублируют чтение и проверки данных из rows, соответствующие операции вынесены в отдельную функцию в папке check_rows.go.
